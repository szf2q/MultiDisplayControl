# 多屏控制管理界面 实施计划

## 1. 摘要

在现有展示程序内部新增一套可视化配置管理界面（Alt+M 打开），实现：

- **软件清单管理**：统一维护桌面应用、网页（以及 PPT）条目，支持新增/编辑/删除/搜索/按类型筛选，支持分层预览。
- **屏幕数量管理**：在当前物理屏范围内增加/移除参与展示的屏幕，数量上限 7（与 Alt+1~7 热键一致）。
- **屏幕布局管理**：展示实际物理屏布局示意，屏幕卡片按配置序号排列，拖拽卡片可调整序号（即 Alt+N 的映射），并可命名屏幕。
- **拖拽分配**：从软件清单拖拽软件到屏幕卡片；同一屏幕内的软件以标签顺序展示，可拖拽调整顺序。
- **配置持久化**：以 `config.json` 为唯一数据源，保存时导出兼容现有启动逻辑的 `config.ini`。
- **增量热更新**：保存后无需重启主程序；仅重排标签时不重启任何应用，新增/移除应用只影响对应屏幕。

## 4. 数据模型与配置存储

### 4.1 数据结构（修改 `ScreenConfig.h`）

```cpp
struct SoftwareItem {
    QString id;            // 全局唯一，格式 sw-<uuid8>
    QString name;          // 显示名称
    QString type;          // web | desktop | ppt
    QString path;          // URL 或本地路径
    QString windowTitle;   // 桌面应用匹配窗口标题 / 网页标题
    QString startupArgs;
    QString remark;
};

struct ScreenAssignment {
    QString softwareId;
    QString tabName;       // 空则使用 SoftwareItem::name
};

struct AppConfig {
    QString id;            // 软件 id（新增，用于运行时稳定匹配）
    // ... 原有字段保持不变
};

struct ScreenConfig {
    QString id;            // scr-<uuid8>
    QString displayName;   // QScreen::name()，物理屏稳定标识
    QRect geometry;        // 保存时的物理屏几何，作为回退匹配
    bool primaryScreen = false;
    // ... 原有字段保持不变
    QList<ScreenAssignment> assignments;  // 配置顺序即标签顺序
};

struct MultiScreenConfig {
    // ... 原有字段保持不变
    QList<SoftwareItem> softwareList;     // 全局软件清单
};
```

`AppConfig` 继续作为运行时结构，由 `assignments + softwareList` 解析生成；`processName` 按现有规则计算。

### 4.3 `ConfigStore`（新增 `ConfigStore.h/.cpp`）

- `static bool load(const QString &dir, MultiScreenConfig *config, QString *error);`
  - 优先读取 `config.json`。
  - 不存在时调用原有 ini 解析逻辑（从 `main.cpp` 迁移 `loadScreenConfig`，行为完全保持），并把每个 `app_N_path` 去重生成 `SoftwareItem`，屏幕 `displayName` 留空。
  - JSON 解析失败时记录错误并回退 ini，不覆盖 JSON。
- `static bool save(const QString &dir, const MultiScreenConfig &config, QString *error);`
  - 生成 `AppConfig` 列表、写 `config.json`（UTF-8、缩进、`QJsonDocument`）。
  - 写前备份：`config.json` → `config.json.bak`；`config.ini` → `config.ini.bak`。
  - 原子写入：先写 `.tmp` 再重命名。
- `static bool exportIni(...)`：手写 UTF-8 ini（不使用 `IniConfiguration::setValue`，避免注释/顺序被 QSettings 打乱），格式与现有完全兼容，并追加扩展键：
  - `screen_display`、`screen_x/y/width/height`、`screen_primary`
  - 旧加载逻辑会忽略这些多出来的键；新加载逻辑优先读 JSON。
- 软件清单按需生成：仅被屏幕引用的桌面应用/网页写入 ini；PPT 条目保持原有 `.ppt` 路径规则。

### 4.4 加载优先级与兼容

1. `config.json` 存在且合法 → 使用 JSON。
2. 否则使用 `config.ini`（现有部署平滑过渡）。
3. 管理界面首次保存后生成 `config.json`，此后 JSON 为唯一数据源。

## 5. 运行时热更新（新增 `DisplayRuntime.h/.cpp`）

### 5.1 接口

```cpp
class DisplayRuntime : public QObject {
    Q_OBJECT
public:
    void start(const MultiScreenConfig &config);   // 首次启动（等价 main 现有两轮流程）
    void apply(const MultiScreenConfig &config);   // 增量应用，返回警告列表
    void shutdown();
signals:
    void applyFinished(const QStringList &warnings);
private:
    QScreen *resolveScreen(const ScreenConfig &screen, int ordinal) const;
    void createScreenWindow(int index, const ScreenConfig &cfg, QScreen *screen);
    void removeScreenWindow(int index);
    void updateScreenWindow(ExternalAppWindow *win, const ScreenConfig &cfg, QScreen *screen,
                            const QStringList &warnings);
};
```

- 继续使用 `GlobalVariants::winList`（key 为屏幕序号字符串）作为窗口索引，保证 Alt+1~7 / Alt+R / Alt+F5 逻辑不变。

### 5.2 物理屏解析 `resolveScreen()`

按以下顺序匹配，命中即返回：

1. `QScreen::name()` 与 `screen.displayName` 完全相等；
2. `QScreen::geometry()` 与 `screen.geometry` 完全相等；
3. 按现有 `sort_screen` 规则排序后取第 `ordinal` 个（兼容旧配置）。

无法匹配时保留配置、不创建窗口，并向 `warnings` 追加“屏幕 N（名称）未连接，已保留配置但未展示”。

### 5.3 增量应用算法

1. 遍历配置屏幕，解析目标 `QScreen`；`appCount == 0` 的屏幕视为“无窗口”，保留配置但不创建窗口。
2. 关闭不再需要的窗口：`hide()` → 立即 `delete`（析构函数会结束该屏外部进程）→ 从 `winList` 移除。
3. 新增窗口：`new ExternalAppWindow(cfg)` → `prestartApps()` → 插入 `winList`；全部新增完成后统一 `loadApps(false)`（保留并发启动优势）。
4. 已存在窗口：
   - 调用 `applyScreenConfig(cfg, screen)` 更新标题、序号、`show_index`、`tab_offset_x`、绑定屏幕（需要时 `setScreen(screen, true)`）。
   - 应用级差异（以 `AppConfig::id` 为键）：
     - 删除：`removeApp(id)`（结束桌面进程 / 销毁网页或 PPT / 移除标签）。
     - 新增：`addApp(app, insertIndex)`。
     - 字段变更（path/title/args）：`removeApp` + `addApp`。
     - 标签名变更：`updateAppTabName(id, tabName)`。
     - 顺序变化：`reorderTabs(orderedIds)`，仅移动标签，不重启任何应用。
5. 全局 `show_index` 变化：对所有窗口 `refreshTabTitles()`，并更新序号浮层。
6. `runAsAdministrator`、`debugMode` 变化无法热应用：保存配置，状态栏提示“需重启主程序生效”。

### 5.4 执行体验

- 保存时管理界面进入“应用中”状态：禁用按钮、显示状态文字、`QApplication::setOverrideCursor(Qt::WaitCursor)`。
- 由于外部程序启动/找窗口可能耗时，`apply()` 同步执行；完成后恢复光标并通过状态栏展示 `warnings`。
- 新增桌面应用的过程中管理界面会短暂无响应，这是现有 `findProcessInfo()`（最多约 30 秒）的既有行为，不额外引入线程与跨线程 UI 调用。

## 6. `ExternalAppWindow` 改造

### 6.1 稳定标识

- 每个标签页控件设置 `widget->setProperty("mdcAppId", app.id)`。
- 新增成员：
  - `QHash<QString, QWidget *> appTabWidgets;`（软件 id → 标签页控件）
  - `QHash<QString, PptSession> pptSessions;`（软件 id → COM 放映会话）
- `ProcessInfo` 增加 `QString appId;`。
- `tabIndexChanged()`、`setScreen()`、`addWindowToTabWidget()` 的匹配从 `tabName` 文本改为 `appId`；`tabName` 仅作为标题展示，避免重排/重名导致显隐错乱。
- 修复 `initTabWidget()` 重复连接 `currentChanged`：连接移入构造函数，使用 `Qt::UniqueConnection`。

### 6.2 新增公开接口

```cpp
void applyScreenConfig(const ScreenConfig &cfg, QScreen *targetScreen);
QStringList appIdsInTabOrder() const;
bool hasApp(const QString &appId) const;
void addApp(const AppConfig &app, int insertIndex);
void removeApp(const QString &appId);
void reorderTabs(const QStringList &orderedAppIds);
void updateAppTabName(const QString &appId, const QString &tabName);
void refreshTabTitles();
```

实现要点：

- `addWindowToTabWidget(widget, app, insertIndex = -1)`：按 `appId` 判断是否已存在并原地替换；否则按指定位置插入；同步维护悬浮 `tabBar`。
- `reorderTabs()`：用 `ui->tabWidget->tabBar()->moveTab(from, to)` 移动页面与标签，`QSignalBlocker` 阻止切换抖动；随后依据 `ui->tabWidget` 的文本与顺序重建悬浮 `tabBar`，恢复当前标签。
- `removeApp()`：倒序清理 `externalAppList` 中 `appId` 匹配项；桌面应用结束进程、网页销毁 `CefWebView`、PPT 结束 COM 会话；移除 `ui->tabWidget` 与 `tabBar` 的标签并 `deleteLater()` 页面控件；清理 `nativeHostWindows` 映射。
- `refreshTabTitles()`：按 `config.showIndex`、`config.screenIndex`、主屏标记重新生成标题；同时刷新 `ui->tabWidget` 与悬浮 `tabBar`，保持当前项。
- PPT：`startAndPlayPpt()` 记录 `PptSession{ control, presentation, timer }` 到 `pptSessions`；`removeApp()` 时停止定时器、`Close()` + `Quit()` 并删除控件。

### 7.4 屏幕布局（`ScreenLayoutCanvas`）

包含三个部分：

1. **物理屏布局示意**：自绘控件，按所有 `QGuiApplication::screens()` 的真实几何等比缩放绘制矩形，标注物理屏名称、分辨率、主屏标记；选中卡片时高亮对应矩形。物理屏变化时（`QGuiApplication::screenAdded/Removed`）重建。
2. **屏序卡片区**：横向流式排列（`QScrollArea`），每张卡片对应一个配置屏，顺序即屏幕序号。卡片内容：
   - 头部：序号徽标、屏幕名称（双击内联编辑）、物理屏名称与分辨率、主屏标记、拖拽手柄。
   - 中部：该屏已分配软件的有序列表（自定义 `AppAssignmentList`）。
   - 底部：`tab_offset_x` 数值框。
   - 拖拽头部到另一张卡片 → 交换两者在列表中的位置（即交换序号），并同步更新所有卡片序号与运行时键映射。
3. **操作栏**：`+ 添加屏幕`（从未绑定的物理屏中选择，最多 7 块）、`删除选中屏幕`（二次确认）。

`AppAssignmentList`（`QListWidget` 子类）：

- `setDragDropMode(QAbstractItemView::InternalMove | DragDrop)`，支持内部重排与外部拖入。
- 外部拖入：解析软件 id，按落点行插入，发出 `softwareDropped(softwareId, row)`。
- 内部重排：`rowsMoved` / `dropEvent` 后发出 `orderChanged(QStringList)`。
- 自定义 `AppChipDelegate` 绘制圆角芯片：类型图标 + 标签名 + 右上角“×”；点击“×”移除，双击打开软件详情。
- 空屏提示“将左侧软件拖到此处”。

**桌面独占规则**：在 `ManagementWindow` 中统一处理分配：
- 若拖入的是桌面应用且已存在于其他屏幕，先从原屏幕移除，再添加到目标屏幕，状态栏提示“已从 N 号屏移入 M 号屏”。
- 同一网页可分配到多个屏幕；同一屏幕内不允许重复分配同一软件。
- 删除软件清单条目时，级联移除所有屏幕中的引用（二次确认）。

### 7.5 预览（`SoftwarePreviewPanel`）

分层预览：

- **软件详情**：桌面应用显示 64×64 系统图标、路径、窗口标题、启动参数；网页显示 URL 卡片与站点域名。
- **网页实时预览**：网页条目提供“加载实时预览”按钮，在面板内创建 `CefWebView` 并加载 URL；再次点击“关闭预览”或切换选中项时销毁视图，避免长期占用内存。桌面应用与 PPT 不提供实时画面，仅展示图标与说明（“运行时将嵌入程序窗口”）。
- **屏幕摘要预览**：选中屏幕卡片时，显示该屏的序号、名称、标签顺序示意条（高亮第一个标签）和已分配软件数量，用于确认拖拽结果。

### 7.6 保存与应用流程

1. 点击“保存并应用”：
   - 从 UI 收集并重建 `MultiScreenConfig`（含软件清单、屏幕顺序、绑定、分配、全局开关）。
   - 校验：至少 1 块屏；每块屏名称可为空；桌面应用不得重复分配；引用必须存在。
   - `ConfigStore::save()` 写 JSON + 导出 ini。
   - 发出 `applyRequested(config)`；`main` 收到后调用 `DisplayRuntime::apply()`。
   - 状态栏显示“已保存并应用”，并列出警告。
2. “重新加载”：若存在未保存修改，二次确认后从磁盘重新读取并刷新全部面板。
3. 保存失败（磁盘只读、JSON 序列化失败）：弹窗提示，不应用运行时。

## 10. 假设与决策

1. **管理界面形态**：主程序内顶级窗口，Alt+M 显示/隐藏；复用已初始化的 CEF 上下文做网页预览。
2. **配置源**：`config.json` 为唯一数据源；每次保存导出 `config.ini`，保证旧部署与旧加载器可用；旧 ini 手工注释在首次保存后不再保留（用户已确认）。
3. **屏幕映射**：以 `QScreen::name()` 为主键，几何为回退；屏幕序号由管理界面卡片顺序决定，不再依赖几何排序。
4. **屏幕数量上限 7**，与 Alt+1~7 一致；超过时提示。
5. **桌面独占、网页可复用**；同一屏内不允许重复。
6. **热更新粒度**：屏幕增删重建窗口；同一屏内应用级增删改；仅顺序变化时只移动标签。
7. **`debugMode`、`runAsAdministrator` 需重启生效**，保存时提示。
8. **PPT 热更新**：尽力结束 COM 放映会话；若目标程序拒绝退出，仅移除标签并记录警告。
9. 不引入第三方库；JSON 使用 Qt Core，图标使用 `QFileIconProvider`。
10. 不修改 `ProcessUtilsWin32Impl.cpp` 等已有未提交改动，不触碰 `3rdparty/`。

## 11. 风险与规避

| 风险 | 规避 |
| --- | --- |
| 按文本匹配标签导致重排后显隐错乱 | 全面改为 `appId` 匹配，`tabName` 仅作展示 |
| 悬浮 `tabBar` 与 `QTabWidget` 数量/顺序不一致 | 重排后统一以 `ui->tabWidget` 为准重建悬浮标签栏 |
| 热更新删除应用时外部进程残留 | 复用/扩展 `stopExternalApp()`，按 `appId` 精确结束进程并清理 `nativeHostWindows` |
| 物理屏未连接/名称变化 | 三级匹配并给出警告，保留配置不丢失 |
| 保存 JSON 时断电损坏 | 临时文件 + 原子重命名 + `.bak` 备份 |
| 新增应用阻塞管理界面 | 等待光标 + 状态提示；沿用现有 30 秒上限，不引入跨线程 UI |
